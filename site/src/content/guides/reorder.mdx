# Reorder

`<Reorder.Group>` and `<Reorder.Item>` make a list the reader puts in order by dragging. Your app owns the order: the group takes it as `values`, and `onReorder` hands each new order back, as an item crosses another.

## From the keyboard

Every group has a keyboard reorder built in, which Motion's doesn't. Each item is a tab stop. Space or Enter lifts the focused item, the arrows move it one place a press (Home and End to the ends), Space or Enter drops it, and Escape puts it back. Each step is read out to a screen reader, from one live region the page shares.

The words are English by default. The group's `announcements` replaces any of them, and `instructions` the instructions read when an item takes focus. `keyboard={false}` turns it off.

## Saving the order

`onReorder` is called at every step, as items cross. To save the order once, say to a server, use the moment a reorder ends with the order changed:

- **On Solid 1,** `onReorderEnd={(end) => save(end.values)}` on the group.
- **On Solid 2,** the group's `reorderEnd` event, from `reorderGroup({ values, onReorder })` given to the group as `groupRef`.

`values` can be a store's array too, on either group. Set it from `onReorder` as the store takes an array: on Solid 1, `setItems(values)` for a root store, or `setState("items", values)` for a field; on Solid 2, which takes it in place, `setItems(() => values)` for a root store, or `setState((draft) => { draft.items.splice(0, draft.items.length, ...values) })` for a field. A signal holding the array is the cheaper of the two: the group reads every item at each step, and a store reads each one through its proxy.

## Its props

- `axis` is `"y"` (a column), `"x"` (a row) or `"xy"` (a grid that wraps). Left out, the group finds it from its items' boxes, as Motion's does; give it when you know it.
- `as` picks the elements: the group is a `ul` and each item an `li` by default.
- An item takes any motion prop but `drag` and `layoutId`, which it sets itself: `whileDrag` for the item in hand, say. Its `layout` is `true` or `"position"`.

## The Features

An item brings its own drag, layout and gestures, so a list works under any provider.

## Thousands of items: Reorder.BatchGroup

`<Reorder.BatchGroup>` and `<Reorder.BatchItem>` reorder a long list of items of one size as one [Batch](/guides/batches). The group gives each item the place its index gives, so no item is measured, as the list mounts or as an item crosses another: a list of thousands mounts and drags at a Batch's cost. Switch the demo to a grid to see one whose columns come from its width.

- **Its shape is a few numbers.** `itemSize` is every item's `{ width, height }` and `gap` the space between places. `axis` is `"y"`, a column (the default), `"x"`, a row, or `"xy"`, a grid, whose `columns` is how many items a row holds: left out, as many as the group's width holds, read again as it's resized.
- **It keeps what `Reorder.Group` gives:** `values` and `onReorder`, the keyboard reorder and its announcements, auto-scroll near its scroll container's edges, the events at a reorder's end, right to left, and a server render with every item at its place. The DOM follows the order, so Tab and a screen reader read the list as it's shown.
- **The motion is the group's props.** `whileDrag`, `whileHover` and `whileTap` are values, or a function of an item and its index; `initial` is those, or `false`; `transition` is the items' moves to their places; and `exit`, for items leaving under an `<AnimatePresence>` around the `<For>`, is values, or a function of an item, its last index and the presence's `custom`. An item is a member of the group's Batch, not a Wardic element, and takes its `value`, `as` and its element's own props.
- **What it gives up:** every item is the one size, and an item has no layout animation, variants or `layoutId` of its own. Its keys are a Batch's, the transforms and `opacity` ([a Batch's limits](/guides/batches#its-limits)). For items of different sizes, or items that need more, use `Reorder.Group`.
- Motion's `Reorder` has no such mode: its tab is a `Reorder.Group` of 1,000 `Reorder.Item`s, each with its own drag and layout animation.

Every prop is on [its reference](/reference/solid/reorder/reorder#reorderbatchgroup-and-reorderbatchitem).

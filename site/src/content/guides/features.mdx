# Shipping less

A `w.*` element animates its values with nothing else: `initial`, `animate`, `exit`, variants and transitions. Each thing it does beyond that, a gesture, layout or a colour space, is a **Feature**: code a page ships only if it asks for it.

## The Features

| Feature | What it brings |
| --- | --- |
| `hover` | `whileHover`, `onHoverStart` and `onHoverEnd` |
| `press` | `whileTap`, `onTap`, `onTapStart` and `onTapCancel`, from the pointer and the keyboard |
| `focus` | `whileFocus` |
| `inView` | `whileInView`, `viewport`, `onViewportEnter` and `onViewportLeave` |
| `pan` | `onPan`, `onPanStart`, `onPanSessionStart` and `onPanEnd` |
| `drag` | `drag`, its constraints, the glide on release, and `dragControls` |
| `layout` | `layout`, `layoutId`, `layoutScroll` and `layoutRoot` |
| `colors` | `oklch()`, `oklab()`, `lab()`, `lch()`, `hwb()` and `color()`. Hex, `rgb()`, `hsl()` and colour names need nothing. |
| `scroll` | a container's scroll, for `createScroll`, which brings it itself |

On Solid 2, the gesture Features bring the ward's events too, such as `"hover"` and `"tap"`. Motion's two sets are here under the same names: `domAnimation` is `hover`, `press`, `focus` and `inView`, and `domMax` is every Feature an element's props use, all but `scroll`. Each is a list, so `[domAnimation, layout]` works wherever Features go.

## A Wardic instance

Choose an app's Features once, in a module of its own, and import its `w` wherever you'd import the binding's:

```tsx
// src/lib/wardic.ts
import { createWardic, domAnimation } from "@wardic/solid"

export const { w } = createWardic(domAnimation)
```

`createWardic` makes a [Wardic instance](/reference/solid/elements/wardic-instance): a `w` whose elements bring those Features wherever they render, and take their props alone. On this one, `<w.div drag />` is a type error, `Type 'boolean' is not assignable to type 'NeedsFeature<"drag">'`, where the binding's `w` would take the prop and do nothing.

A page that drags or lays out makes an instance of its own:

```tsx
// src/lib/wardic-drag.ts: for the pages that drag
import { createWardic, domAnimation, drag } from "@wardic/solid"

export const { w } = createWardic([domAnimation, drag])
```

The module that makes an instance ships its Features to every page that imports it, so give a page's Features a module only its pages import: the pages that don't drag never load `drag`. An instance with `layout` returns the layout hooks too, `useAnimateLayout`, `createInstantLayoutTransition` and `createResetProjection`, which bring it.

## Loaded later

An entry in the list can be a load:

```tsx
// drag-feature.ts holds `export { drag } from "@wardic/solid"`, so the import is a chunk of its own.
export const { w } = createWardic([domAnimation, () => import("./drag-feature.ts").then((m) => m.drag)])
```

It starts in the browser the first time one of the instance's elements or wards is made, or one of its hooks is called, and once for the instance, however many pages use it. While it loads:

- Values animate at once, and each Feature takes effect as it arrives. A drag tried before `drag` has arrived does nothing, and isn't replayed.
- An element with a layout prop starts laying out when `layout` arrives: it animates its next layout change.
- The server loads nothing: it renders each element at its starting style, as it always does.

## For a section

An instance's Features are named where its module is written. A section gives Features in the three cases that can't be: `<WardicProvider features>` to everything under it, and `<LazyWardic features>` to a part of the tree. The binding's own `w`, imported from `@wardic/solid`, has those of its section, its provider's and every `LazyWardic`'s between them; it takes every prop, and a prop whose Feature isn't there does nothing. An instance's elements have them too, beside their own.

- **A subtree you don't make:** a component library's elements are its own `w.*`, or the binding's; a `LazyWardic` around them gives them what they use.
- **Features handed over at runtime:** in the [storefront](https://solid2.wardic.dev), moving a piece from Saved for later flies its photo into the cart, with the `layout` of the page it came from. The page hands it over, `arrive(piece, layout)`, and the cart's fly-in is a `LazyWardic` given it: the shell, on every page, never imports `layout` itself.
- **A load at each render:** a `LazyWardic` whose `features` is a function loads as it renders, every time it renders. Rendered on a press, it loads on that press, as below; an instance's load runs once.

**Components and hooks that need a Feature bring it:** `Reorder.Item` brings `drag`, `layout` and the gestures, `Reorder.Group` brings `layout`, and `createScroll` brings `scroll`. `LayoutGroup` brings `layout` for its own `layoutDependency` only: a layout element under it still needs `layout` from its instance or its section.

## A Feature left out

On an instance's element, a prop of a Feature the instance hasn't got is a type error that names the Feature, and so, on Solid 2, is listening for its event on the instance's ward.

On the binding's `w`, the prop does nothing: `whileHover` without `hover` doesn't play, `drag` without `drag` doesn't drag, and an `oklch()` colour without `colors` isn't read as a colour. In development, Wardic warns once for each Feature, naming it and where to add it.

## Every Feature at once

`wardic.*` is the element with every Feature, whatever its section has, and so are `wardic.create` and the ward that isn't `w`'s: `createWard` on Solid 1, `ward()` on Solid 2. It's handy for trying something out, and heavy for a page. `strict` on a `WardicProvider` or a `LazyWardic` makes one throw in development, so none reaches a page by accident.

## What it saves

Measured on Solid 1's binding at 1.0.0-rc.3, built as an app ships and gzipped, each over the Slim element alone, 97 KB for the whole app:

| Feature | Size |
| --- | --- |
| `hover` | 4 KB, the input every gesture but `inView` stands on included |
| `press`, `focus` and `inView`, after `hover` | 2 KB |
| `drag`, after `domAnimation` | 6 KB |
| `layout` | 20 KB |
| `colors` | 4 KB |
| Every Feature, a `wardic.*` element | 36 KB |

# Many elements at once

A Wardic element carries its own animation: its values, its springs, and the work of starting and stepping them. A few dozen on a page cost little. For hundreds or thousands of like elements moving on the same keys, such as a grid's tiles, a long list or a chart's points, `createBatch` animates them as one **Batch**. Every member's values, speeds and targets are kept together, and each frame steps them all in one run. Changing a thousand members' targets costs about a twentieth of changing them one at a time, and each frame about half ([measured](/why#fast-where-motion-happens)).

## A grid that shuffles

<Demo sample="batch" />

<CodeTabs sample="batch" />

- **One Batch for the grid,** keyed by tile: `each` is the order, and `key` each tile's id. `animate(tile, i)` gives a tile its place from its index in the order now, so a new order turns every tile toward its new place in one change, each from where it is and at the speed it has. Press Sort while they're still on their way and each one changes course without stopping.
- **`tiles.member(id, { style })`** is a tile's handle, spread onto its element. Give the element's own `style` to the handle, not beside it: the Batch draws `transform` and `opacity` over the rest.
- **The tiles render once.** `<For each={TILES}>` makes the thousand elements, and a new order changes only what the Batch reads.
- **`stagger()`** counts the tiles a change moves, so the wave runs through the ones that go somewhere.
- **"Moving…" and "Ready"** come from the Batch's landings: on Solid 2 `tiles.settled()`, pending while any tile moves; on Solid 1 `onAnimationStart` and `onAnimationComplete`. The frame rate is the page's own readout, the frames it drew in each second ([`site/samples/frames.ts`](https://github.com/wardiclabs/wardic/blob/main/site/samples/frames.ts)).

The demo's Mosaic and Lines turn the same tiles to Wardic's mark, a tile to each of its cells, or shrunk and turned along its strokes: each drawing is one change of the Batch's targets, as a shuffle is. They're the demo's alone ([`demo.tsx`](https://github.com/wardiclabs/wardic/blob/main/site/samples/batch/demo.tsx)).

Motion has no Batch. Its tab runs the same grid through `animate()`, a call per tile, as [`createAnimate`](/reference/solid/animation/create-animate) would.

## Sierpiński's triangle, at scale

<Demo sample="sierpinski" />

<CodeTabs sample="sierpinski" />

Its 2,187 leaves are always mounted, one Batch by index (`count`), and at depth `d` they cover `3 ** d` triangles, 243 at depth 5. Each leaf has an address, its number in base 3: at each level a 0 takes its triangle's top half, a 1 its bottom-left and a 2 its bottom-right. At depth `d`, a leaf sits on its ancestor `d` levels down, so the leaves sharing one cover it as one triangle:

```ts
// triangle.ts
export const leafAt = (i: number, depth: number): { x: number; y: number; scale: number } => {
  let x = 0
  let y = 0
  let scale = 1
  let leavesUnder = LEAVES
  for (let level = 0; level < depth; level++) {
    leavesUnder /= 3
    const half = HALVES[Math.floor(i / leavesUnder) % 3]
    x += half.x * scale * WIDTH
    y += half.y * scale * HEIGHT
    scale /= 2
  }
  return { x, y, scale }
}
```

Its sizes, `HALVES` (each half's top-left corner as a share of its triangle) and the colours are in [`triangle.ts`](https://github.com/wardiclabs/wardic/blob/main/site/samples/sierpinski/triangle.ts).

The slider changes the depth, and `animate: (i) => leafAt(i, depth())` turns every leaf toward its new place in one change. Drag it back and forth and the leaves carry their speed through each turn. "A ward each" runs the same triangle with a Wardic element per leaf: compare the frame rate while it moves.

## Hover and press

<Demo sample="batch-gestures" />

<CodeTabs sample="batch-gestures" />

- **`whileHover` and `whileTap`** move a member while the pointer is over it and while it's pressed, as a Wardic element's do. A press that ends with the pointer still over it goes back to the hover's values.
- **Here `whileHover` lifts the hovered swatch** from its own row: a function of its index, since a swatch's `y` is where it sits, and values would send every swatch to one row. A function's keys must be keys the Batch already has. Given as values, a gesture's keys join the Batch's, and go back to where they were as it ends.
- **Its neighbours grow with it.** `hoverStart` puts the hovered swatch in a signal, and `animate` scales every swatch by its distance from it: 1.25 on it, less with each cell away. A new hover is one change for all 120, and leaving the palette clears it.
- **The tap** tells you which member: `onTap`'s `{ i }` on Solid 1, `swatches.when("tap")`'s on Solid 2, with `item` too when keyed. Each swatch is a `<button>`, so Enter and Space press it; a member that isn't focusable is given `tabindex="0"`.
- **One set of listeners** on the window hears every swatch, however many there are, where each of Motion's 120 buttons listens for itself. The gesture code loads with the first Batch that needs it.

## Items that come and go

<Demo sample="batch-presence" />

<CodeTabs sample="batch-presence" />

- **Keyed by name,** its `each` is the filtered list. Filter an item out and it leaves the list, and the rest turn toward their new places in the same change: each one's place is its index, so they need no `layout`.
- **Under `<AnimatePresence>`,** a leaving item plays its `exit` before its element goes. `stagger()` in the exit's transition counts the items leaving together.
- **An item back** enters from `initial`. Switch filters before an exit lands and the items coming back turn around where they are, at the speed they have, their old elements gone at once.
- Motion's tab gives every item `layout`, and its presence `mode="popLayout"`, so a leaving item gives up its place in the grid as it fades.

## What else a Batch does

Each of these is on [`createBatch`'s page](/reference/solid/animation/create-batch):

- **Landings.** Pending while anything moves, then how many members set off. [Its landings](/reference/solid/animation/create-batch#its-landings).
- **From code.** `animate(grid, …)` with Playback controls, a member's own call, and a Batch as a sequence's Segment. [Animating it from code](/reference/solid/animation/create-batch#animating-it-from-code).
- **One member that does more.** A Wardic element on a member's element drags, or runs variants or a hover of its own, and hands its keys back to the Batch once it's done. [A Wardic element as a member](/reference/solid/animation/create-batch#a-wardic-element-as-a-member).
- **Server rendering.** Each member renders its start, so a hydrated page doesn't jump. [Server rendering](/reference/solid/animation/create-batch#server-rendering).

A list the reader puts in order is a Batch too: [`Reorder.BatchGroup`](/guides/reorder#thousands-of-items-reorderbatchgroup) places thousands of items of one size and keeps `Reorder`'s drag, keyboard and announcements.

## Its limits

- **Its keys are the transforms and `opacity`,** as numbers: `px` for a move, degrees for a turn, unitless for a scale. A colour, a size or any other style is a Wardic element's.
- **Every member has the same keys,** the Batch's: the ones its first targets and starts give, joined by the keys of an `exit`, `whileHover` or `whileTap` given as values. A keyed Batch can take `keys` up front instead. A key a later `animate` gives is an error.
- **A member has no variants, drag or layout of its own.** Make its element a Wardic element for variants or a drag, as above. Layout animations aren't a member's: its Wardic element can't have `layout` or `layoutId`.
- **Members inside an `<svg>` leave at once** under `<AnimatePresence>`, for now.

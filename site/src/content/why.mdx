# Why Wardic

Wardic gives Solid the API of Motion for React, on an engine built with [Effect](https://effect.website). Three things set it apart: it's fast where motion happens, it keeps Motion's API while working the Solid way, and you can replace any part of its engine. Two more come with it: animations that play before your JavaScript loads, and observability built in.

## Fast where motion happens

Wardic steps every animation on a page on one Frame loop, and draws what they all write together, once a frame. Measured against Motion, the work done while things move takes about half of its time or less: retargeting an animation, unmounting, and each frame while animations run.

| 1,000 elements, ms | Wardic, Solid 1 | Wardic, Solid 2 | Motion 14.9 |
| --- | --- | --- | --- |
| Mount | 37.7 | 38.8 | 39.4 |
| A page's first mount | 62.3 | 68.3 | 53.4 |
| Retarget while running | 17.1 | 16.3 | 43.6 |
| Retarget at rest | 16.6 | 16.3 | 36.4 |
| Unmount | 2.6 | 2.8 | 12.0 |
| A frame while animating | 3.12 | 2.99 | 5.50 |

Lower is faster. Mounting is where Motion keeps up: see [what it costs](#what-it-costs).

Measured on 2026-11-06, Wardic 1.0.0-rc.2 (`main` at f8afa96) against Motion for React 14.9.0 (`framer-motion`), in Chromium 147.0.7727.15, on an AMD Ryzen 7 9700X (8 cores, 16 threads) with 62 GiB, on Ubuntu 24.04.5 with Linux 6.8: 1,000 elements, each task timed with the two frames after it (an unmount with one), the median of 11 repetitions. A page's first mount is its first round. `bun run bench:motion` runs it again: its pages and protocol are in [`packages/solid/bench/motion`](https://github.com/wardiclabs/wardic/tree/main/packages/solid/bench/motion). Each run's results are in [#519](https://github.com/wardiclabs/wardic/issues/519#issuecomment-6682285847).

## Motion's API, the Solid way

A `w.div`, with the Features its provider gives, takes what a `motion.div` takes: `initial`, `animate`, `exit` and `transition`, variants that pass down the tree, hover, press, focus, drag and pan, layout and shared-element animations, presence, and values that follow the scroll or the pointer. What changes is Solid's:

- **A component runs once,** so Wardic reads its props as they change, and nothing re-renders.
- **Hooks are `create*` primitives,** as Solid names them.
- **On Solid 2, an element's events come from its ward.**

Its values are typed: a bare number is taken only where it means something, and on a length it's drawn in `px`. [Coming from Motion](/motion) maps every API.

## Animations before the JavaScript loads

On a server-rendered page, an element's mount animation, when the server knows all of it, plays from the first paint. The server samples it, from Wardic's own springs and tweens, into a CSS animation in the page's head, so it runs before any code arrives, and to its end with JavaScript off. When the client hydrates, it takes the animation over where it has got to, its speed included. See [server rendering](/guides/server-rendering).

## Built on Effect: replace any part

Wardic's engine asks for what it needs as Effect services: a clock, a renderer, its input, the page's measurements, the kinds of value it blends, the default transitions. `@wardic/dom` provides them for the browser, most of them as `DomLive`, and the provider's `env` takes any Layer that gives them. So you can replace parts of it:

- **the default transitions,** which keys spring and which tween;
- **the kinds of value,** so colours blend in OKLCH;
- **the announcer,** to speak through your own live region;
- **the renderer;**
- **tracing, logs and failure reports,** Effect's own.

Otherwise Effect stays out of your way: an app hands its provider `DomLive` and writes Solid.

## Observability, built in

Every animation runs in its own span, the Frame loop keeps metrics when you give it `FrameLoopMetrics`, and Wardic logs what it does at Debug. Hand your provider Effect's tracing, logging or failure reporting once, beside `DomLive`, and every animation reports through it. In development, you can turn on a frame check that fails an animation whose frame holds a NaN, and names the key. See [observability](/guides/observability).

## What it costs

- **Size.** One Wardic element is 104 KB gzipped on Solid 1 and 132 KB on Solid 2, for the whole app, Solid included. On Solid 1, about two fifths of the minified code is Effect's runtime, half is Wardic's engine and binding, and the rest is Solid's and the colour library's. Gestures, layout and the wider colour spaces are Features, shipped only where a provider or a `LazyWardic` gives them, and the [1.1 milestone](/roadmap#11-size-and-speed) works on the base.
- **Mounting.** A mount takes about as long as Motion's, but a page's first mount takes longer, while the engine sets up and its code first runs.
- **Effect.** `effect` is a dependency you install beside Wardic.

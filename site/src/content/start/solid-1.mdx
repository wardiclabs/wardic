# Start on Solid 1

Wardic's root entry, `@wardic/solid`, is its binding for Solid 1 (`1.9`), and it follows semver from `1.0.0`, its [Effect-typed parts](/roadmap#10-motions-api-on-solid) moving to a new Effect major only in a Wardic major. It works in a plain Solid app and in SolidStart, rendered on the server or not.

## Install

`effect` and `solid-js` are peers: Wardic uses the copies your app has.

## The provider

Every Wardic element sits under one `WardicProvider`. It takes the environment Wardic runs in: `DomLive` in a browser.

```tsx
import { DomLive } from "@wardic/dom"
import { WardicProvider } from "@wardic/solid"
import { render } from "solid-js/web"

render(
  () => (
    <WardicProvider env={DomLive}>
      <App />
    </WardicProvider>
  ),
  document.getElementById("app")!,
)
```

In SolidStart, put it in `app.tsx`, around the router's root, so every page shares one:

```tsx
import { Router } from "@solidjs/router"
import { FileRoutes } from "@solidjs/start/router"
import { DomLive } from "@wardic/dom"
import { WardicProvider } from "@wardic/solid"
import { Suspense } from "solid-js"

export default function App() {
  return (
    <Router
      root={(props) => (
        <WardicProvider env={DomLive}>
          <Suspense>{props.children}</Suspense>
        </WardicProvider>
      )}
    >
      <FileRoutes />
    </Router>
  )
}
```

## Your app's Features

What an element does beyond animating its values, a gesture, layout or a colour space, is a [Feature](/guides/features), code a page ships only if it asks for it. Choose your app's once, in a module of their own: `domAnimation` is hover, press, focus and in-view.

```tsx
// src/lib/wardic.ts
import { createWardic, domAnimation } from "@wardic/solid"

export const { w } = createWardic(domAnimation)
```

Import `w` from it, not from `@wardic/solid`. Its elements take those Features' props, and a prop of another is a type error that names it. These guides import it as `~/lib/wardic.ts`, SolidStart's alias for `src`; in a plain Vite app, import it by its path.

## Your first element

A `w.*` element takes Motion's props: it animates from `initial` to `animate`, and to its `whileHover` target while the pointer is over it.

The same motion can go on an element of your own, with a ward: `w.createWard(config)` spread onto it, or the `use:w` directive.

```tsx solid1
import { w } from "~/lib/wardic.ts"

export function Card() {
  const card = w.createWard({ initial: { opacity: 0 }, animate: { opacity: 1 } })
  return <div class="card" {...card()} />
}
```

## Only what a page uses

A page that drags or lays out makes an instance of its own, in a module only its pages import, so the pages that don't never load `drag` or `layout`:

```tsx
// src/lib/wardic-drag.ts
import { createWardic, domAnimation, drag } from "@wardic/solid"

export const { w } = createWardic([domAnimation, drag])
```

[Shipping less](/guides/features) has the rest: loading a Feature later, and the sections a `LazyWardic` makes.

## Rendered on the server

On a server-rendered page, an element arrives in the HTML already at `initial`, so it never flashes at its target first. Its entrance plays from the first paint, before the JavaScript has loaded, and the client takes it over mid-flight when it hydrates.

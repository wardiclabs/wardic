# createBatch

Animates many elements on the same keys as one Batch: each member's values, speeds and targets are kept together, and every frame steps them all in one run. Changing a thousand members' targets costs about what one element's change does, and each member turns toward its new target at the speed it already has.

```tsx
import { createBatch, stagger } from "@wardic/solid" // or "@wardic/solid/unstable/v2"

const grid = createBatch({
  count: 100,
  animate: (i) => ({ x: (order()[i] % 10) * 48, y: Math.floor(order()[i] / 10) * 48 }),
  transition: { type: "spring", visualDuration: 0.4, bounce: 0.2, delay: stagger(0.005) },
})
<For each={cells}>{(i) => <div class="cell" {...grid.at(i)} />}</For>
```

Call it in a component under a `WardicProvider`: the component's cleanup stops it. On a server it animates nothing, and each member's element renders with its own props.

## Its config

- **`count`:** how many members it has, read once.
- **`animate(i)`:** member `i`'s targets. What it reads is tracked: when it changes, every member turns toward its new targets in one change. A member whose targets didn't change is left alone.
- **`initial`:** where each member starts, values or a function of its index. Without it, a member starts at each key's identity (`x: 0`, `scale: 1`, `opacity: 1`) and animates to its targets as it mounts, as a Wardic element with no `initial` does. With `initial: false`, it starts at its targets.
- **`transition`:** a Wardic element's: a spring or a tween, each key's own under its name, else the nearest `WardicConfig`'s, else each key's Default transition. Reduced motion and `skipAnimations` apply as on any animation. Its `delay` is seconds, or `stagger()`, which counts only the members a change moves: delete one item of a long list and the few that shift start at once.

Its keys are the transforms and `opacity` (**`WardicBatchKey`**), as numbers: `px` for a move, degrees for a turn, unitless for a scale. They're the ones its first targets and starts give: a key a later `animate` gives is an error.

## Its members

`grid.at(i)` is member `i`'s handle: spread it onto its element. Give the element's own `ref` and `style` beside it, `grid.at(i, { ref, style })`: its `style` is kept, without the properties the Batch draws (`transform` and `opacity`).

A member has no gestures, variants or layout of its own: for those, use a Wardic element. An element inside an `<svg>` turns about its own centre, as an HTML one does.

## Its landings

On Solid 2, `grid.settled()` is an async value: pending while any member moves, then the landing, `{ moved }`, how many members set off. `grid.next("settled")` is a promise of the next one, and `grid.when("settled")` every one, for an effect:

```tsx
import { createBatch } from "@wardic/solid/unstable/v2"
import { isPending } from "solid-js"

<p>{isPending(() => grid.settled()) ? "Moving…" : "Ready"}</p>
```

On Solid 1, `onAnimationStart` is called as members set off from rest, and `onAnimationComplete(landing)` once every one is at rest again.

## Animating it from code

[`createAnimate`](/reference/solid/animation/create-animate)'s `animate` takes a Batch, or one member's handle, and returns the same playback controls it returns for an element: `await` it, pause it, seek it, change its speed, complete, cancel or stop it.

```tsx
const [scope, animate] = createAnimate()
const shuffle = () => animate(grid, { x: (i) => colX(order[i]), y: (i) => rowY(order[i]) }, { type: "spring", delay: stagger(0.002) })
animate(grid, { opacity: [0, 1] })              // two stops: every member from 0, to 1
animate(grid, { y: (i) => [-2, rowY(i)] })      // two stops for each member
animate(grid.at(42), { scale: 1.4 })            // one member
```

Each key takes a number for every member, two stops (its first and its target), or a function of the member's index and the Batch's count that gives one or two. Its keys are the Batch's. A later change of a member's key, by the config's `animate` or another call, takes it: that member goes the later change's way, and the call it left doesn't finish, as a Wardic element's doesn't. A call that moves nothing finishes at once.

A member's element moves its member too. `animate(tile, { x: 40, backgroundColor: "tomato" })` moves `x` in the Batch, as `animate(grid.at(i), { x: 40 })` does, and `backgroundColor` as on any element, under one set of controls. A selector or a list of members moves them as one call over them, in the list's order, and its `stagger()` counts the members that move. Through an element, a Batch's key takes a number or two stops. A transform the Batch draws without having it as a key, such as `rotate` on a Batch of `x` and `y`, is an error: the Batch draws the element's whole `transform`.

A Batch can be a [sequence](/reference/solid/animation/sequences)'s Segment too, `[grid, { x: (i) => colX(order[i]) }, options]`. Each member runs through its own stops in the Batch, and the sequence's controls drive it with the rest. There, a key takes a number, `null`, stops, or a function that gives them, and a Segment's `stagger()` counts its members.

## Coming from Motion

Motion has no Batch: its `animate(elements, …)` runs each element on its own, as [`createAnimate`](/reference/solid/animation/create-animate) does. A Batch is for the collections where that cost shows: hundreds or thousands of like elements moving at once.

## Types

- **`WardicBatchConfig`:** its config. **`WardicBatchValues`:** a member's values. **`WardicBatchTransition`:** its transition, its `delay` a `stagger()` too.
- **`WardicBatch`:** what it returns. **`WardicBatchMember`:** a member's handle. **`WardicBatchMemberProps`:** the element's own props a handle takes.
- **`WardicBatchLanding`:** a landing, `{ moved }`. **`WardicBatchEvents`:** (Solid 2) its events, for `next` and `when`.
- **`WardicBatchSubject`:** what `animate` takes for a Batch, a Batch or a member's handle. **`WardicBatchTarget`:** its targets there. **`WardicBatchStop`:** one stop, a number or a function of a member's index and the count, that gives a number.

# Reorder

`Reorder.Group` and `Reorder.Item` make a list the reader puts in order by dragging its items, or from the keyboard. Your app owns the order: the group takes it as `values`, and `onReorder` hands each new one back, as an item crosses another. See [Reorder](/guides/reorder).

```tsx
import { Reorder } from "@wardic/solid" // or "@wardic/solid/unstable/v2"

const [items, setItems] = createSignal(["Bowls", "Plates", "Cups"])
<Reorder.Group values={items()} onReorder={setItems}>
  <For each={items()}>{(item) => <Reorder.Item value={item}>{item}</Reorder.Item>}</For>
</Reorder.Group>
```

Key the items with `<For>`, by their values. An item brings its own drag, layout and gestures, so a list works under any provider.

`values` can be a store's array. Set it from `onReorder` as the store takes an array: on Solid 1, `setItems(values)` for a root store or `setState("items", values)` for a field; on Solid 2, `setItems(() => values)` for a root store or a splice of the field in a draft. A signal holding the array is the cheaper input: the group reads every item at each step, and a store reads each one through its proxy. See [Saving the order](/guides/reorder#saving-the-order).

## Reorder.Group

| Prop | |
| --- | --- |
| `values` | The list's values, in order: an array, or a store's. |
| `onReorder` | Given each new order, as an item crosses another: set `values` from it. |
| `axis` | `"y"`, a column, `"x"`, a row, or `"xy"`, a grid that wraps. Left out, it's found from the items' boxes, as Motion's is; give it when you know it. |
| `as` | The element it renders: `"ul"` by default. Read once. |
| `keyboard` | `false` turns the keyboard reorder off: the items have no keys, no tab stop and no instructions. |
| `announcements` | What a screen reader hears at each step of a keyboard reorder, over the English defaults: `lift`, `step`, `drop`, `cancel`, and `move`, each a function of the item's `label`, `position` and the list's `count`. |
| `instructions` | What each item's `aria-describedby` reads, over the English default. |

Beside them, the element's own props and [motion props](/reference/solid/elements/props). It gives the element `overflow-anchor: none`, so the browser doesn't scroll the page as items move.

To hear a reorder end, say to save it once:

- **On Solid 1,** `onReorderEnd={(end) => save(end.values)}`, with `onHoldStart` and `onHoldEnd` for an item taken in hand and let go.
- **On Solid 2,** make the group with [`reorderGroup`](/reference/solid/reorder/reorder-group) and give it as `groupRef`, the options its config doesn't set beside it, or give a function as `groupRef`, which is handed the group the component makes. Either way, its `reorderEnd`, `holdStart` and `holdEnd` events.

```tsx
import { Reorder, reorderGroup } from "@wardic/solid/unstable/v2"

const list = reorderGroup({ values: items, onReorder: setItems })
createEffect(list.when("reorderEnd"), (end) => save(end.values))
<Reorder.Group groupRef={list} axis="x">…</Reorder.Group>
```

## Reorder.Item

| Prop | |
| --- | --- |
| `value` | Its value in the group's `values`. Read once. |
| `layout` | `true`, its place and size animating (the default), or `"position"`, its place alone, its size changing at once. |
| `as` | The element it renders: `"li"` by default. Read once. |

Beside them, the element's own props and any motion prop but `drag` and `layoutId`, which the group sets: `whileDrag` for the item in hand, say. Each item is a tab stop for the keyboard reorder; your own `tabIndex` (Solid 2: `tabindex`) wins over its `0`, and your `aria-describedby` ids come before its instructions. Outside a `Reorder.Group` it throws.

On Solid 2, an item made with [`reorderItem`](/reference/solid/reorder/reorder-item) can be given as `wardRef`, to hear its events, with the props its config doesn't set beside it; or a function as `wardRef` is handed the item's ward.

## Reorder.BatchGroup and Reorder.BatchItem

A long list reorders as one [Batch](/guides/batches): `Reorder.BatchGroup` places each item at the place its index gives, from its size and the sizes before it, never measuring it at a crossover, so a list of thousands mounts and drags at a Batch's cost. Its items are one size, or each its own, given by a function or read from the page. It drags, steps from the keyboard, speaks and ends a reorder as `Reorder.Group` does, and the DOM follows the order.

```tsx
<Reorder.BatchGroup values={items()} onReorder={setItems} itemSize={{ width: 240, height: 48 }} gap={8} whileDrag={{ scale: 1.03 }}>
  <For each={items()}>{(item) => <Reorder.BatchItem value={item}>{item}</Reorder.BatchItem>}</For>
</Reorder.BatchGroup>
```

| Prop | |
| --- | --- |
| `values`, `onReorder`, `keyboard`, `announcements`, `instructions`, `as` | As `Reorder.Group`'s. Each value is its own: it's its item's key. |
| `axis` | The list's shape: `"y"`, a column (the default), `"x"`, a row, or `"xy"`, a grid that wraps. |
| `itemSize` | Every item's size, `{ width, height }` in px; or a function giving each item's, `(item, i) => ({ width, height })`, called for every item at each change of the list, and tracked: a size it reads that changes moves the items after it. In a column, `width` left out (`{ height: 48 }`, or a function's) makes each item as wide as the group's content box, its padding and border inside, and the group sets no width of its own. Left out, each item's size is read from the page: its own content's, in a column its height alone, its width the group's. |
| `gap` | The space between places, in px: one for both axes, or `{ x, y }`. |
| `columns` | A grid's columns, its items one size: how many a row holds. Left out, as many as the group's width holds, read again as it's resized: give the group its width, say `width: 100%`. With a function `itemSize` or none, a type error: each row holds the items that fit the group's width, the next row below the tallest of the one before, each item at its row's top, as CSS's `flex-wrap`. |
| `direction` | `"rtl"` mirrors a row's and a grid's places, from the group's right edge. Left out, the group's element's own direction, so a page's `dir="rtl"` needs none; on a server, `"ltr"` unless given. |
| `initial` | Where each item starts: values, a function of its item and index, or `false`. It starts at its place, but for the keys `initial` gives, and its entrance moves those to their identity: `initial={{ opacity: 0 }}` fades each item in. |
| `transition` | How the items move to their places. |
| `appear` | `true` plays the items' entrance from the first paint of a server-rendered page, as [a Batch's](/reference/solid/animation/create-batch#its-entrance-from-the-first-paint). Off by default. |
| `whileDrag` | Where an item goes while it's in hand, dragged or lifted from the keyboard: values with an optional `transition`, or a function of its item and index. |
| `whileHover`, `whileTap` | Where an item goes while the pointer is over it, and while it's pressed: by a pointer, or by Enter or Space while the keyboard reorder is off (on, they lift it). |
| `exit` | Where an item leaving under `<AnimatePresence>` goes, at its last place: values with an optional `transition`, or a function of its item, last index and `custom`. Put the `<AnimatePresence>` around the `<For>`. |

The group is `position: relative`, sized to its places; each item is `position: absolute` at the start of the group's content box (its padding kept), sized from `itemSize`, placed by its transform. On a server each item renders at its place, so hydrating moves nothing; a grid with no `columns`, or of items each their own size, is laid out there by CSS (CSS grid, or `flex-wrap`), as the server can't know its width, and placed by the group once it reads it. A column whose items take its width has it on a server too: once placed, each item is as wide as the group's padding box less the group's padding, read as it mounts and as the group's size changes; on a server, a column of one size or a function's is a CSS size container (`container-type: inline-size`) and each such item `100cqi` wide until then, what a container query inside its items measures, and its own stacking context. Items whose sizes are read are laid out in flow, as a flex column, a flex row or `flex-wrap` rows, the gap CSS's, until their first sizes are read, on a server and on a client alike: then each is placed where flow had it. One observer reads every item's size, always on: a size that changes (an image loading, a row's text wrapping again) moves the items after it on the group's transition, and the group's own size follows a frame later. An item's margins count in flow but not in its place: space them with `gap`. An item's own DOM events (`onClick`, say) work as on any element; the group tells no gesture events of its own. An item is a member of the group's Batch, not a Wardic element: it takes its `value`, `as` (`"li"` by default), and its element's own props, its `style` without a transform or `opacity` the Batch draws. Its events are as `Reorder.Group`'s: on Solid 1, `onReorderEnd`, `onHoldStart` and `onHoldEnd`; on Solid 2, a function as `groupRef` is handed the group, with its `next`, `each` and `when` of `reorderEnd`, `holdStart` and `holdEnd`, its `move` and its `axis`.

## Coming from Motion

Motion's `Reorder`, with its props. Wardic adds the keyboard reorder, which Motion's lacks, and the events for a reorder's end and an item taken in hand.

## Types

- **`ReorderGroupProps`:** (Solid 1) `Reorder.Group`'s props. On Solid 2, the props a group's spread gives its element, as on [its page](/reference/solid/reorder/reorder-group).
- **`ReorderItemProps`:** (Solid 1) `Reorder.Item`'s props.
- **`ReorderGroupComponentProps`**, **`ReorderItemComponentProps`:** (Solid 2) `Reorder.Group`'s and `Reorder.Item`'s props. **`ReorderGroupOf`**, **`ReorderItemOf`:** their group and item: the config as props, or one made beforehand given as `groupRef` or `wardRef`.
- **`GroupRefCallback`:** (Solid 2) a function `groupRef` hands the component's group.
- **`ReorderElementTag`:** a tag `as` takes.
- **`ReorderItemLayout`:** an item's `layout`, `true` or `"position"`.
- **`ReorderBatchGroupProps`**, **`ReorderBatchItemProps`:** `Reorder.BatchGroup`'s and `Reorder.BatchItem`'s props. **`ReorderBatchItemSize`:** an item's size, `itemSize`'s. **`ReorderBatchColumnSize`:** an item's size in a column, its `width` optional. **`ReorderBatchSizing`:** `axis`, `itemSize` and `columns` together, the ways they go: `columns` with one size, and a size with no `width` in a column. **`ReorderBatchGap`:** `gap`.
- **`ReorderBatchGroup`:** (Solid 2) the group a `Reorder.BatchGroup`'s `groupRef` is handed.

>
> - [ADR-0001](../adr/0001-core-stream-contract.md) — core primitives return `Stream<Frame>` (not `Atom`); reactivity is a binding concern; physics frames carry `velocity`.
> - [ADR-0002](../adr/0002-rendering-paths.md) — primitives are sink-free; the Renderer splits into a pure `project` and an imperative `commit`; the Solid declarative surface renders reactively (since #79, [ADR-0034](../adr/0034-the-gate-commits-every-element.md): only its Starting style; the flush gate commits every frame).
> - [ADR-0003](../adr/0003-ssr-initial-value-contract.md) — initial values are resolved synchronously via `project(resolveInitial(config))`, and the same value pins the stream's `from`.
> - [ADR-0004](../adr/0004-recognition-in-core-response-in-binding.md) — gestures and layout split into **recognition** (core: `hover`/`press`/`drag`/`inView`/`focus` Recognizers, `flip`, `resolveOverrides`, the drag→decay Fling) and **response** (binding: variant naming, tree propagation, lifecycle timing, JSX). This supersedes the plan sections below that place `createDrag`/`createHover`/`createLayout`/`<LayoutGroup>`/`<AnimatePresence>` *logic* in `@wardic/solid` — those become thin wrappers over core recognizers. `InputSource` gains a focus/blur stream; scroll is deferred.
>
> Other locked decisions (no ADR): a separate `chase` primitive for moving-target follow; tween interruption restarts from current value over full duration; a fixed engine `dt` clamp at the `fromClock` boundary; an `InterpolatorRegistry.resolve(from, to) => (t)=>T` API resolved once per key; color matching via culori's `parse`; `velocityOf` reads `dt` from `Clock`; a `respectReducedMotion(stream)` combinator with snap default; `repeat: Infinity` supported in core; multi-form modifiers wired uniformly via `animate`. Where this document and those sources disagree, **the sources are authoritative.**

A reactive, services-based animation engine built on Effect v4 (using its in-core reactivity at `effect/reactivity`). Framework-agnostic core; first-class Solid bindings for v0.1 with expressive declarative APIs including variant orchestration.

## What Wardic Is

Wardic is an animation engine designed around a single architectural premise: **environments are services, not packages with parallel APIs**. The animation primitives live in `@wardic/core` and ask for what they need (a clock, a renderer, an input source, a measurement probe) via Effect's typed dependency injection. Environment packages provide Layer implementations of those services.

The consequence: the same animation code runs in any environment that has a corresponding Layer. New environments are added by writing a Layer, not by reimplementing the engine. The library is built on Effect v4 (including its in-core reactivity), but Effect is invisible to consumers. Solid users see Solid signals, idiomatic `createX` hooks, and a unified `useWardic` API; the Effect machinery is doing structural work underneath.

**v0.1 ships with Solid bindings only**, but it's a feature-complete binding — not a minimal one. The Solid API includes variant orchestration, layout animations, presence, gestures, and SSR-correct rendering. React, Vue, web components, React Native, and Canvas are explicitly deferred — the architecture supports them as additive future work.

## Why Effect

**Effect v4** gives us typed dependency injection (Services and Layers), structural resource management (Scope), correct cancellation propagation (Fibers), first-class async, and built-in observability (`Effect.withSpan` integrates with OpenTelemetry). The v4 runtime is small — a minimal program is ~6.3kb gzipped, ~20kb with Stream and Schema. Reactivity ships in-core via `effect/reactivity` (Atom, AtomRegistry), so there is no `@effect-atom/atom` dependency.

Core animation primitives are `Stream`-based rather than `Atom`-returning (see [ADR-0001](../adr/0001-core-stream-contract.md)): cancellation maps cleanly onto Stream/Scope teardown, and the reactive cell views read is a binding-layer concern (Solid signals via the binding, Atom for canvas/imperative consumers, etc.). The substrate provides typed services for dependency injection, structural resource scoping, first-class async via Stream and Effect, and built-in tracing.

## Architectural Philosophy

**Services define what's needed; Layers provide implementations.** The animation engine declares its dependencies as Effect services. Environments provide Layer implementations. Animation code never imports environment-specific modules.

**The library API lives in `@wardic/core`.** Environment packages export Layers, not parallel APIs. A consumer wires up an environment once at app startup; all subsequent code is environment-agnostic.

**Effect is invisible to users.** The Solid bindings expose `useWardic`, `createAnimate`, `wardic.create(Component)`. Effect machinery underneath is structural work users don't think about. Power users who know Effect can drop down to custom Layers; everyone else gets a clean animation library.

**dt over absolute time.** Animations consume delta time and accumulate locally. The clock's absolute value is reference-only.

**Physics primitives for momentum, definite primitives for finite motion.** `spring`/`decay` carry velocity (preserved across interruption via the binding's cached Snapshot); `chase` follows a continuously-moving target indefinitely; `tween`/`animate`/`keyframes` scrub cleanly. Architectural recommendation, not enforcement.

**SSR-correct by default.** Initial animation state is computed during render and applied via spread props, so server-rendered HTML arrives at the client already in the correct initial state. No flash-of-unanimated-content.

## Services Defined in Core

Five services form the abstraction layer between the engine and its environments. All five are defined in `@wardic/core` from day one, even though v0.1 only ships implementations for DOM and Test.

### Clock

Time source. Exposes the current time, the most recent dt, and a stream of dt values.

```ts
class Clock extends Context.Service<Clock, {
  readonly time: Atom.Atom<number>
  readonly dt: Atom.Atom<number>
  readonly ticks: Stream.Stream<number>
  readonly tick: (t: number) => Effect.Effect<void>
}>()("@wardic/Clock") {}
```

### Renderer

Output for the imperative render path. Per [ADR-0002](../adr/0002-rendering-paths.md), the Renderer's responsibilities split into a pure **project** (engine values → environment representation, e.g. DOM transform grouping) and an imperative **commit** (write a projected patch to the target). The reactive render path (Solid declarative) uses `project` alone and feeds the result into a signal.

```ts
class Renderer extends Context.Service<Renderer, {
  readonly project: (values: Record<string, unknown>) => Record<string, unknown>
  readonly commit: <T>(target: T, patch: Record<string, unknown>) => Effect.Effect<void>
}>()("@wardic/Renderer") {}
```

### InputSource

Raw event streams from the environment.

```ts
class InputSource extends Context.Service<InputSource, {
  readonly pointer: (target: unknown) => Stream.Stream<PointerLikeEvent>
  readonly keyboard: () => Stream.Stream<KeyboardLikeEvent>
  readonly wheel: (target: unknown) => Stream.Stream<WheelLikeEvent>
}>()("@wardic/InputSource") {}
```

### Probe

Environment introspection — measurement, viewport, motion preferences.

```ts
class Probe extends Context.Service<Probe, {
  readonly measure: (target: unknown) => Effect.Effect<Bounds>
  readonly viewport: Atom.Atom<{ width: number; height: number }>
  readonly prefersReducedMotion: Atom.Atom<boolean>
  readonly observeResize: (target: unknown) => Stream.Stream<Bounds>
  readonly observeIntersection: (target: unknown) => Stream.Stream<boolean>
}>()("@wardic/Probe") {}
```

### InterpolatorRegistry

Pluggable value-type registry.

```ts
class InterpolatorRegistry extends Context.Service<InterpolatorRegistry, {
  readonly register: <T>(entry: InterpolatorEntry<T>) => Effect.Effect<void>
  /** Resolve once per pair at stream construction; the hot path holds the bound `(t) => T`. */
  readonly resolve: <T>(from: T, to: T) => Effect.Effect<(t: number) => T>
  /** Sugar over `resolve` for one-off interpolation. */
  readonly interpolate: <T>(from: T, to: T, t: number) => Effect.Effect<T>
}>()("@wardic/InterpolatorRegistry") {}
```

### `@wardic/core`

The engine. Defines all five services. Implements `animate`, `spring`, `tween`, `decay`, `chase`, the utility surface. Ships built-in interpolators (number, array, color via culori, unit-string). Depends on `effect@4.x` (including its in-core reactivity), `culori`, `bezier-easing`. No environment-specific code.

### `@wardic/dom`

Browser environment Layers. `ClockDomLive` (rAF-driven), `RendererDomLive`, `InputDomLive`, `ProbeDomLive`, `InterpolatorsDomLive` (CSS calc, transforms, viewport units, advanced color). Exports `DomLive` as the composed Layer.

### `@wardic/test`

Headless testing Layers. All five services mocked. Exports `TestLive`. Tests provide it instead of `DomLive`; animation code under test is unchanged.

### `@wardic/solid`

The Solid framework binding. Bridges core's frame streams into Solid signals (using `effect`'s in-core reactivity where the binding needs an `Atom` shape). Provides the layered API documented below. Peer-deps `solid-js`.

## Engine Animation Primitives

Each primitive returns a `Stream` of `Frame`s driven by the `Clock` — `{ value, done }` for definite primitives, with an added `velocity` (a `PhysicsFrame`, narrowed via `isPhysicsFrame`) for physics primitives. Per [ADR-0001](../adr/0001-core-stream-contract.md) this replaces the original `Atom`-returning shape; the reactive cell views read is a binding-layer concern.

```ts
tween(from, to, options):              Stream<Frame<number>, never, Clock>
animate(from, to, options):            Stream<Frame<number>, never, Clock>
keyframes(stops, options):             Stream<Frame<number>, never, Clock>
spring(target, options):               Stream<PhysicsFrame, never, Clock>
chase(getTarget, options):             Stream<PhysicsFrame, never, Clock>   // never auto-settles
decay(initial, velocity, options):     Stream<PhysicsFrame, never, Clock>
animateValues(from, to, options):      Stream<Frame<Values>, never, Clock | InterpolatorRegistry>
springValues(target, options, from?):  Stream<Frame<Record<string, number>>, never, Clock>
animateFrom(current, to, options):     Stream<Frame<number>, never, Clock>
```

The `R` parameter on each Stream encodes its service dependencies; the compiler enforces that a Layer providing those services is in scope. Interruption is the binding's responsibility — it caches the last frame as a **Snapshot** and constructs a fresh primitive seeded from it (carrying velocity for physics primitives, just value for definite). See [ADR-0001](../adr/0001-core-stream-contract.md) for the full reasoning.

## The Solid Binding API

The Solid binding is the v0.1 user surface. It's a layered design — low-level primitives for fine-grained control, a unified `useWardic` hook as the primary API, sugar layers (`wardic.create()`, `use:ward`) for common patterns, and orchestration components (`<AnimatePresence>`, `<LayoutGroup>`) for composition. All layers compose with each other and share the same context system.

### Setup

```tsx
import { render } from "solid-js/web"
import { WardicProvider } from "@wardic/solid"
import { DomLive } from "@wardic/dom"
import App from "./App"

render(
  () => (
    <WardicProvider env={DomLive}>
      <App />
    </WardicProvider>
  ),
  document.getElementById("root")!,
)
```

`WardicProvider` sets up the Atom runtime with the right Layer. For SSR, swap `DomLive` with a server-appropriate Layer.

### `useWardic` — the primary API

`useWardic` is the high-level hook that powers everything else. It's SSR-correct by default (initial styles spread into JSX so server-rendered HTML matches the client's first frame), supports variants and orchestration, and composes with the layered animation/gesture/layout primitives.

```tsx
import { useWardic, easeOutCubic } from "@wardic/solid"

function Hero() {
  const ward = useWardic({
    initial: { opacity: 0, y: 20 },
    animate: { opacity: 1, y: 0 },
    transition: { duration: 0.3, easing: easeOutCubic },
  })

  return <div {...ward()}>Hero content</div>
}
```

`ward` is a callable object with attached properties:

```ts
type Ward<V extends Variants = never> = {
  // Callable: returns spreadable props for the rendered element
  (): {
    ref: (el: HTMLElement | undefined) => void
    style: Record<string, string | number>
    onPointerEnter?: () => void
    onPointerLeave?: () => void
    onPointerDown?: (e: PointerEvent) => void
    onPointerUp?: (e: PointerEvent) => void
    // additional event handlers for gestures
  }
  /** Provider for variant propagation to children */
  Provider: Component<{ children: JSX.Element }>
  /** Imperative controls — pause, play, stop, programmatic transitions */
  controls: AnimationControls
  /** Direct atom access for advanced composition */
  state: Atom.Atom<AnimationState>
}
```

Why this shape:

**SSR-correct.** The `style` field is computed synchronously during render from `initial`. The server emits HTML with the initial styles already applied. The client hydrates without a visual snap.

**Composable with other props.** Spread `ward()` alongside other JSX props naturally:

```tsx
<div {...ward()} class="my-card" data-testid="hero">
```

**Reactive.** `ward()` is an accessor — it re-evaluates when the animation state changes. Solid tracks the spread reactively.

**Self-contained lifecycle.** The ref callback wires up the animation atoms on mount; cleanup happens via `onCleanup` plus Effect's Scope. No manual disposal.

### Variant orchestration

The signature feature of declarative animation libraries: named animation states (variants) that propagate through the component tree.

```tsx
import { useWardic, springs } from "@wardic/solid"
import { For } from "solid-js"

function NavMenu(props: { isOpen: boolean }) {
  const ward = useWardic({
    variants: {
      closed: { opacity: 0, x: -200 },
      open:   { opacity: 1, x: 0 },
    },
    initial: "closed",
    animate: () => (props.isOpen ? "open" : "closed"),
    transition: {
      type: "spring",
      ...springs.gentle,
      staggerChildren: 0.05,
      delayChildren: 0.1,
    },
  })

  return (
    <ward.Provider>
      <nav {...ward()}>
        <For each={menuItems}>
          {(item) => <NavItem label={item.label} href={item.href} />}
        </For>
      </nav>
    </ward.Provider>
  )
}

function NavItem(props: { label: string; href: string }) {
  // No `initial` or `animate` — inherits the current variant from the parent.
  const ward = useWardic({
    variants: {
      closed: { opacity: 0, y: 10 },
      open:   { opacity: 1, y: 0 },
    },
  })

  return (
    <a {...ward()} href={props.href}>
      {props.label}
    </a>
  )
}
```

When `props.isOpen` flips, the parent's variant changes, propagating through the `ward.Provider` context to all `NavItem` children. Each child has its own matching `"open"` variant and animates accordingly. Stagger is applied automatically based on child mount order.

**Variant resolution priority:**
1. Local `animate` prop (if explicitly provided)
2. Parent context's variant (if a Provider is in the tree)
3. `initial` (first frame only)

**Context value exposed by `ward.Provider`:**
```ts
interface WardicContextValue {
  variant: Accessor<string | undefined>          // reactive current variant
  transition: TransitionConfig                    // default transition for children
  staggerChildren?: number                        // delay between siblings
  delayChildren?: number                          // delay before first child
  staggerDirection?: 1 | -1                       // 1 = forward, -1 = reverse
  from?: "first" | "last" | "center" | number     // stagger origin
  when?: "beforeChildren" | "afterChildren"       // ordering between parent and children
  registerChild: () => { index: Accessor<number>; dispose: () => void }
}
```

**Stagger and ordering:**
- Children register on mount; the Provider assigns them indices in mount order.
- When a child unmounts, its index is freed but other children retain theirs (no animation re-runs from unrelated removals).
- For reactive lists rendered with `<For>`, keying by ID preserves animation identity across reorders.
- `when: "beforeChildren"` delays children until the parent's animation completes; `"afterChildren"` reverses the order.

### `wardic.create()` — declarative HOC

Sugar built on `useWardic` for the most common case: animating a single element or wrapped component.

```tsx
import { wardic, springs } from "@wardic/solid"

// Wrap an HTML element
const AnimatedBox = wardic.create("div")

// Wrap a custom component (must forward refs)
const AnimatedCard = wardic.create(Card)

function App() {
  return (
    <>
      <AnimatedBox
        initial={{ opacity: 0, y: 20 }}
        animate={{ opacity: 1, y: 0 }}
        transition={{ duration: 0.3 }}
      >
        Box
      </AnimatedBox>

      <AnimatedCard
        initial={{ scale: 0.95 }}
        animate={{ scale: 1 }}
        whileHover={{ scale: 1.05 }}
        whileTap={{ scale: 0.95 }}
        transition={{ type: "spring", ...springs.gentle }}
      >
        Card
      </AnimatedCard>
    </>
  )
}
```

The HOC internally calls `useWardic`, splits motion props from the wrapped component's props, and applies the spread automatically. SSR-correct because it builds on `useWardic`.

For components that need to participate in variant propagation, expose them as the inner element of a `ward.Provider` from a parent. The HOC supports all the same motion props (`initial`, `animate`, `variants`, `exit`, `whileHover`, `whileTap`, `whileDrag`, `drag`, `layout`, `transition`).

### `use:ward` — directive (client-only)

For client-only apps where SSR doesn't matter, the directive shape is concise.

```tsx
import { ward } from "@wardic/solid"

function SubscribeButton() {
  return (
    <button use:ward={{
      whileHover: { scale: 1.05 },
      whileTap: { scale: 0.95 },
      transition: { type: "spring", ...springs.wobbly },
    }}>
      Subscribe
    </button>
  )
}
```

The directive is sugar for `useWardic` plus a manual ref. **Important caveat:** the directive runs only after hydration, so initial styles aren't applied to server-rendered HTML. Use `useWardic` or `wardic.create()` for SSR contexts; the directive is documented as "client-only — for SSR use `useWardic`."

### Lower-level `createX` primitives

For fine-grained control or use cases the high-level API doesn't cover, the imperative primitives are available.

```ts
// Imperative animation control
createAnimate(ref, from, to, options): Controls

// Reactive springs (chase a moving target)
createSpring(target, options): SpringControls

// Tweens with reactive targets
createTween(target, options): Controls

// Decay (fling math, for momentum after gestures)
createDecay(initial, velocity, options): DecayControls

// Gestures
createDrag(ref, options): DragControls
createHover(ref): HoverState

// Environment observation
createInView(ref): InViewState
createScroll(ref?): ScrollState
createReducedMotion(): boolean

// Lifecycle
createPresence(show, exitFn): PresenceState
createLayout(ref): void

// Reactive helpers
createTransform(source, mapper): T
createVelocity(signal): number
```

These can be used directly when you want to compose animations imperatively or apply them to elements not managed by `useWardic`/`wardic.create()`. The high-level API uses these internally.

### Orchestration components

**`<AnimatePresence>`** — manages exit animations for children. Children unmount only after their `exit` variant animation completes.

```tsx
import { wardic, AnimatePresence } from "@wardic/solid"
import { Show, createSignal } from "solid-js"

const Toast = wardic.create("div")

function Notifications() {
  const [visible, setVisible] = createSignal(false)

  return (
    <>
      <button onClick={() => setVisible((v) => !v)}>Toggle</button>

      <AnimatePresence>
        <Show when={visible()}>
          <Toast
            initial={{ opacity: 0, y: 40 }}
            animate={{ opacity: 1, y: 0 }}
            exit={{ opacity: 0, y: 40 }}
          >
            Saved!
          </Toast>
        </Show>
      </AnimatePresence>
    </>
  )
}
```

Variant inheritance works naturally — if `AnimatePresence` is inside a `ward.Provider`, exiting children inherit the parent's exit variant when one is defined.

**`<LayoutGroup>`** — coordinated layout animations across siblings. Elements with matching `layoutId` props animate between positions when one is replaced by another.

```tsx
import { wardic, LayoutGroup } from "@wardic/solid"

const Item = wardic.create("div")

function TabSelector(props: { selected: string }) {
  return (
    <LayoutGroup>
      <For each={tabs}>
        {(tab) => (
          <Item layout class="tab">
            {tab.label}
            <Show when={tab.id === props.selected}>
              <Item layoutId="indicator" class="indicator" />
            </Show>
          </Item>
        )}
      </For>
    </LayoutGroup>
  )
}
```

The `indicator` element animates between tabs as `props.selected` changes — FLIP animation orchestrated through `LayoutGroup`'s context.

## Observability and Tracing

Every animation primitive attaches an `Effect.withSpan`. Hook up OpenTelemetry once at app entry to get hierarchical traces of every animation.

```ts
import { OtlpTracer } from "@effect/opentelemetry"
import { DomLive } from "@wardic/dom"
import { Layer } from "effect"

const TracingLive = OtlpTracer.layer({
  resource: { serviceName: "my-app" },
  url: "https://otel-collector.example.com",
})

const AppLive = Layer.mergeAll(TracingLive, DomLive)
```

Production telemetry gives you performance attribution per animation, causality across the app, and the foundations for future `@wardic/devtools` work.

## Implementation Order

The v0.1 happy path:

1. **Monorepo setup.** Bun workspaces, TypeScript project references, Changesets, basic CI. Empty package skeletons for `@wardic/core`, `@wardic/dom`, `@wardic/solid`, `@wardic/test`.

2. **`@wardic/core` service definitions.** All five Context.Services. No implementations yet, just contracts.

3. **`@wardic/test` Layer implementations.** Mock implementations of all five services.

4. **`@wardic/core` interpolation registry.** Built-in interpolators: number, array, color (via culori), unit-string. Tested via the test Layer.

5. **`@wardic/core` easings and utilities.** Pure functions.

6. **`@wardic/core` animation primitives.** `animate` (scalar + multi-property), `spring` (scalar + multi-property), `chase`, `tween`, `decay`. Frame-level tests.

7. **`@wardic/core` advanced utilities.** `velocityOf`, `stagger`, `group`, `delay`, `wait`, `animateFrom`, modifiers, keyframes, `onFrame`, `onSettle`, `noise`, `snap`, `pulse`, `wave`.

8. **`@wardic/dom` Layer implementations.** rAF clock driver, style/transform renderer, pointer/keyboard/wheel input, getBoundingClientRect/ResizeObserver/IntersectionObserver probe, DOM-specific interpolators. The `DomLive` composed Layer.

## Design Principles

**Services are the abstraction; everything pluggable.** Anything that varies by environment is a service.

**Effect is invisible to users.** Framework bindings expose familiar shapes. Power users can drop down to Effect directly.

**Same animation code, any environment.** A `useWardic` call works in any environment with a corresponding Layer.

**SSR-correct by default.** Initial state is computed during render and applied via spread props.

**Resource management is structural.** Effect's Scope guarantees cleanup.

**Tracing is first-class.** Every animation primitive wraps in `Effect.withSpan`.

**dt over absolute time.** Animations are insensitive to clock magnitude.

**Physics primitives for momentum, definite primitives for finite motion.** `spring`/`decay` carry velocity through binding-driven interruption; `chase` follows a moving target; `tween`/`animate`/`keyframes` scrub cleanly. Architectural recommendation.

**Variants over imperative coordination.** Declarative variant orchestration scales to complex component trees better than imperative animation calls.

**Composability with the broader reactive ecosystem.** Atoms compose with other atoms.

**Color quality.** Depend on `culori` for proper color-space interpolation.

## What This Is Not

**Wardic is not a drop-in replacement for Motion or Framer Motion.** It covers similar surface area with different architecture.

**Wardic does not require users to know Effect.** The Solid bindings hide everything.

**Wardic does not tie animations to Solid.** Solid is the first binding because of architectural alignment, but the engine is framework-agnostic.

**Wardic does not promise feature parity with mature libraries.** Motion, GSAP, and anime.js have years of edge-case debugging. v0.1 is alpha; production maturity takes time.

## Open Questions

**~~SSR initial value resolution for reactive `initial`.~~** Resolved by [ADR-0003](../adr/0003-ssr-initial-value-contract.md): static or variant-name `initial` is SSR-serialized; function `initial` is client-only first-frame (may flash). The decidable rule is "is it a function?"; the binding should dev-warn when it sees one.

**~~WAAPI handoff in `@wardic/dom`.~~** Resolved (deferred): WAAPI is a browser-only, *transparent* optimization that does not alter the public contract, so it is **post-v0.1**. It is structurally the deferred sibling of ADR-0006's central coordinator — an alternative *driver* for an eligible subset, slotting into the same driver indirection. When built, it lives in `@wardic/dom` + the Solid binding (not core; WAAPI's non-per-frame nature also doesn't fit the `project`/`commit` Renderer shape). **Eligibility predicate** (what can ever hand off): definite primitives or *static-target* springs (pre-sampled into a `linear()` easing), animating composited props (transform/opacity), not being actively retargeted. `chase`, drag direct-set, runtime-velocity `decay`, and gesture-churned retargets stay tick-driven. Handed-off animations forfeit per-frame `Frame`s and `wardic.*` spans, and require value read-back (+ resample for velocity) to retarget — which is why only the eligible subset hands off. v0.1 reserves the seam by keeping execution behind the driver indirection; it ships no WAAPI code. **The first eligible case is a scroll-linked value (#240):** a scroll progress, or a range transform of one, drawn into `opacity` or `transform` by an animation on a native `ScrollTimeline` / `ViewTimeline`, as Motion's `useScroll` does. It needs no retarget and no velocity, and a read can compute it from the scroll. Measured: a gate-drawn one is a frame behind a compositor scroll, up to three with a busy main thread (ADR-0043 *Note (#240)*; the lab's scenario 19 shows the gap).

**Performance characteristics at scale.** Effect's fiber runtime has non-zero per-operation cost. Typical UI workloads are fine; extreme cases need measurement.

**~~Color interpolation default.~~** Resolved: default to **OKLab** (perceptually uniform, cartesian — no surprise hue-arcs; matches CSS `color-mix`/gradient defaults). The current `colorInterpolator("rgb")` in `interpolate/registry.ts` is gamma sRGB — the perceptually *wrong* space (muddy/dark midpoints) — and must change to `"oklab"`. Perf is a non-issue at realistic color-animation counts. Per-call opt-out (`lrgb`/`rgb` for extreme counts) and opt-in (`oklch` for deliberate hue-arcs) are **deferred** until there's demand; meanwhile power users override globally by registering `colorInterpolator(mode)` at the env. When per-call lands, it takes the shape of an opaque, entry-interpreted hints bag — `resolve(from, to, options?)` where color reads `options.colorSpace` — added as an optional, backward-compatible param so the generic `InterpolatorRegistry` contract never hardcodes color.

**~~Public Effect API surface.~~** Resolved (see [ADR-0008](adr/0008-public-api-tiers.md)): three tiers — Tier 1 stable Effect-free (binding API + core values/types/utils), Tier 2 advanced Effect-typed (primitives/services/Layers/combinators; "stability tracks Effect"), Tier 3 `@internal` (steppers, `chaseCore`, registry internals; removed from public `index.ts`). Curate the barrels to stop leaking Tier 3; hard subpath split deferred.

**~~`wardic.create()` ref forwarding.~~** Resolved: `wardic.create(Component)` requires the component to forward its `ref` to a single root DOM element — the only requirement (style + input are applied through that element, so no style/handler prop-forwarding is needed). A wrapped element registers with the ADR-0006 flush gate using a **commit sink** (`Renderer.commit(el, patch)`) rather than a signal sink; element-string wraps keep the signal sink. If the ref never populates after mount, throw a clear, actionable dev error (no-op in prod). Auto-wrapper-div and explicit ref-getter API were rejected (silent layout/measurement breakage; boilerplate, respectively).

**~~Stagger reordering semantics.~~** Resolved (see [ADR-0007](adr/0007-variant-orchestration.md)): stagger delays are snapshotted at transition-trigger time from the child order at that instant; a reorder mid-transition does not reshuffle in-flight delays, and the next variant change recomputes from the new order. Core's `stagger(amount, opts): (index, total) => delay` stays pure; the binding owns the snapshot + index/total.

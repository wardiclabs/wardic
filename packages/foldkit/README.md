# @wardic/foldkit

[Wardic](https://wardic.dev) for [Foldkit](https://www.npmjs.com/package/foldkit): Motion's animations on Foldkit's views, as Effect. Private until Wardic 1.2 ships it (#561).

```ts
import { DomLive } from "@wardic/dom"
import * as Wardic from "@wardic/foldkit/Wardic"

// Once, at module scope.
export const wardic = Wardic.make({ env: DomLive })

// In the view: `w.*` elements take Foldkit's attributes and Wardic's.
const view = (model: Model, h: HtmlBuilder<Message>): Html => {
  const w = wardic.html(h)
  return w.div([h.Class("app")], [
    w.div([h.Class("card"), w.Initial({ opacity: 0, y: 8 }), w.Animate({ opacity: 1, y: 0 }), w.Transition({ duration: 0.3 })], [model.title]),
  ])
}
```

- The first `w.*` element to mount builds Wardic's services on the Handle's `env`, shared until the last has left. `w.Provider(options)` on the `w.*` element at the top names the root the subtree options hang on.
- An element animates its `Animate` target from `Initial` as it mounts, Retargets on a render that changes its target, and holds through one that doesn't.
- `h.div([...w.attributes({ initial, animate, transition, style, mount })])` puts a Ward on an element `w` doesn't make.
- Variants go down the DOM: a child with `w.Variants(…)` and no `Animate` of its own follows the name its nearest `w.*` ancestor hands down, staggered by that ancestor's `Transition` (`staggerChildren`, `delayChildren`, `when`). `w.Custom(value)` resolves its dynamic variants; `w.Inherit(false)` keeps it out.
- `arc({ strength })` (from the root) is a curved path for a transition's `path`: `x` and `y` travel along it together, as a `layoutId` flight's `w.Transition({ layout: { path } })`.
- `w.Config({ transition, reducedMotion, skipAnimations })` sets a subtree's defaults, over the Handle's `Wardic.make({ config })`.
- `w.OnAnimationStart(message | (definition) => message)` and `w.OnAnimationComplete(…)` send Messages to `update`; `Option.none()` from a function sends nothing.
- Live values are Atoms: `w.Style({ x: atom })` follows one through the gate, `w.Text(atom)` writes one as the element's text, `w.OnUpdate(atom)` sets one to the element's values each frame. Derived ones (`LiveValue.spring`, `follow`, `velocity`, `scroll`, re-exported from the root) are made in a Command through `Wardic.provide(effect)`, with `resources: wardic.resources` on the program; their Scope is the caller's, a `ManagedResource`'s or an `Effect.scoped`. `provide` gives the Handle's Features' services too: `LiveValue.scroll` asks for the `scroll` Feature's, so a Handle that reads a container's scroll is made with `Features.scroll` among its features (Solid's `createScroll` brings it by itself).
- `Wardic.animate(subject, values, options)` is an Effect for a Command: an element, a selector or a list, landing as `{ landed }`, failing `AnimationFailed` when the subject finds nothing; interrupting its fiber stops it where it is. `Wardic.animate(sequence, options)` plays a sequence of Segments laid out in time (`[["li", { opacity: 1 }, { delay: stagger(0.05) }], "shown", ["h1", { y: 0 }, { at: "shown" }]]`, with `at` times, labels and function Segments as Motion's), failing only when nothing in it animates.
- Animation scopes: `const scope = AnimationScope.make()` (from the root), `w.AnimationScope(scope)` on one element, then `Wardic.animate("li", values, { scope })` (either form) looks its selectors up inside that element; the element's release stops the animations started in the scope where they are, each awaiting Command then succeeding with `landed: false`; `scope.element()` is the element while it's mounted. Without a scope a selector resolves under the `w.Provider()` element, else the document; a scope not mounted finds nothing.
- A Retarget a patch makes paints its first step in the patch's frame: the binding tells the Frame loop it runs inside the frame (the **Held frame**'s cure).
- Presence: `w.ul([w.Presence({ mode, initial, custom, onExitComplete, propagate })], items.map((key) => w.keyed("li")(key, [w.Exit({ opacity: 0 }), …], [key])))` keeps each item Foldkit removes in its place while its `Exit` plays, in Motion's order through the patches that follow; one back under its key mid-exit takes over from where the leaver is. It needs `Wardic.make({ env, features: [Features.presence] })`, with `Features` from the root.
- Layout: `w.li([w.Layout(true)])` animates from where it was to where a patch put it, measured by a pass after every patch that changed the DOM (the child list, the text, `class` and `hidden`; `Wardic.make({ layoutAttributes })` adds yours; never `style`). `w.LayoutId("pill")` hands over across two views, and `w.LayoutCrossfade(false)` on the twin that takes over keeps one element visible through the handover, at its own opacity; `w.LayoutGroup({ id })` on an ancestor keeps its ids apart; `w.LayoutDependency(value)` asks for a pass as it changes; it and `Wardic.animateLayout` are the only triggers under `Wardic.make({ layoutTrigger: "declared" })`. `w.OnLayoutAnimationStart(message)` and `w.OnLayoutAnimationComplete(message)` send Messages; `w.OnBeforeLayoutMeasure(fn)` and `w.OnLayoutMeasure(fn)` are plain functions. It needs `Features.layout`. Put `w.Provider()` on the app's root: the observer then watches the app's tree alone, not the body (Foldkit's DevTools paint into it).
- `Wardic.animateLayout()` is an Effect for a Command run with the Model change that moved the layout elements: it waits for the render's commit, animates the change from where the elements were, and succeeds once every layout animation has ended; `LayoutFailed` without `Features.layout`.
- `Runtime.makeElement({ viewTransition: wardic.viewTransition(decide) })` wraps the app's predicate: in a render it transitions, layout moves and `layoutId` handovers land at once, for the View Transition's morph to carry; without `document.startViewTransition`, Wardic animates them itself.
- Gestures: `w.WhileHover({ scale: 1.05 })`, `w.WhileTap({ scale: 0.95 })`, `w.WhileFocus(…)` (the keyboard's focus) and `w.WhileInView(…)` with `w.Viewport({ once, margin, amount, root: "#scroller" })` (`root` a selector under the view, or `"parent"`) are entries in the Override stack, a name among them reaching the element's Variant children. `w.OnHoverStart(message | (event, info) => message)`, `w.OnHoverEnd(…)`, `w.OnTapStart(…)`, `w.OnTap(…)` and `w.OnTapCancel(…)` send Messages with the DOM's event and the gesture's info (its point in the viewport; a press's input, `"pointer"` or `"keyboard"`: Enter and Space press a focused element, which is made focusable); `w.OnViewportEnter(message | (entry) => message)` and `w.OnViewportLeave(…)` the browser's entry. A function runs at the event, so `event.stopPropagation()` works; its Message reaches `update` a microtask later. `w.Propagate({ tap: false })` keeps a press to its element. Each needs its Feature, `Features.hover`, `press`, `focus` or `inView` (`Features.domAnimation` is the four): without it the attribute is a type error naming the Feature.
- Drag: `w.div([w.Drag("x"), w.DragConstraints("parent"), w.WhileDrag({ scale: 1.05 }), w.OnDragEnd((event, info) => Message.Dropped({ x: info.offset.x }))], …)` follows the pointer on its axis and carries on at the speed it was let go. `w.DragConstraints` takes a box of pixels, `"parent"`, a selector under the view, or `false`; `w.DragElastic(0.2)`, `w.DragMomentum(false)`, `w.DragSnapToOrigin()`, `w.DragTransition({ power, timeConstant })`, `w.DragPropagation()`, `w.DragDirectionLock()` with `w.OnDirectionLock((axis) => message)`, `w.DragListener(false)` and `w.OnMeasureDragConstraints(fn)` are Motion's props; `w.OnDragStart(…)`, `w.OnDrag(…)` and `w.OnDragEnd(…)` send Messages with the drag's info (its offset, delta, velocity and point), `w.OnDragTransitionEnd(message)` once the element rests. The drag's options are read as its track starts, at the first render with `Drag`: give a changed one on a new key. The element gets `touch-action`, `user-select: none` and `draggable="false"` under its own `h.Style`. With `w.Layout()` the drag moves the element within its layout, and it returns to its slot on release. It needs `Features.drag`.
- Drag controls: `const controls = DragControls.make()` (from the root), `w.DragControls(controls)` on the element and `w.StartsDrag(controls, { snapToCursor })` on the grip it drags by (give the grip `touch-action: none`); `w.DragListener(false)` keeps the element's own presses from dragging it; `controls.stop()` and `controls.cancel()` end its drag from anywhere.
- Animation controls: `const controls = AnimationControls.make()` (from the root), `w.Animate(controls)` on any number of elements, then from a Command `AnimationControls.start(controls, "visible", transition?)`, an Effect that succeeds once each element and its Variant children have landed and, interrupted, stops them where they are; `controls.set(definition)` lands them at once and `controls.stop()` ends them where they are, both synchronous (`Effect.sync`). A definition is a variant name, a target, or a function of the element's `Custom`, called once per element. An element keeps the controls it mounted with: key it to mount it with others. On a server it renders its `Initial` and plays nothing until a start.
- Pan: `w.OnPanSessionStart(…)`, `w.OnPanStart(…)`, `w.OnPan(…)` and `w.OnPanEnd(…)` send Messages as a pointer pans the element, which moves nothing itself. `w.Config({ transformPagePoint })`, or `Wardic.make({ config: { transformPagePoint } })`, maps a drag's and a pan's points: `correctParentTransform(parent)` turns them back through a parent's CSS transform, `transformViewBoxPoint(svg)` into an SVG's viewBox units, each given an element, an accessor or a selector looked up in the document at each point (both from the root). It needs `Features.pan` (`Features.domMax` is every DOM Feature).
- Reorder: `w.ul([w.ReorderGroup({ values: model.items, onReorder: (items) => Message.Items({ items }) })], items.map((key) => w.keyed("li")(key, [w.ReorderItem(key)], [key])))` puts the keyed items in order by dragging them, or from the keyboard (Space lifts, the arrows move, Space drops, Escape cancels, each announced). The order lives in the Model: `onReorder` sends the whole new order at each Crossover; `onReorderEnd`, `onHoldStart` and `onHoldEnd` send Messages too; `axis`, `keyboard`, `announcements` and `instructions` are Motion's and Wardic's options. Each item is a layout element (`w.Layout("position")` beside it moves its place alone) dragged on the group's axis; a `StartsDrag` element inside it, with `w.DragListener(false)` and `w.DragControls(controls)` on the item, drags it by that element alone. It needs `Features.layout` and `Features.drag`. `wardic.Reorder` is the group's Mount for a Scene test.
- Features load lazily too: `Wardic.make({ env, features: () => import("./features.ts").then((m) => m.domMax) })`. An element mounted before the load arrives starts its gestures, its drag's track and its layout node once it has.
- Server rendering: Foldkit's `renderToString` (its `experimental/server`, `makeApplication` programs only) renders every `w.*` element at its Starting style with no runtime and no Mount, as a server does: a Variant child's inherited one included under `w.Provider()`, and a `w.Presence({ initial: false })` child's `Animate`. Put one `w.Provider()` on the topmost `w.*` element: the walk that writes them starts there, a `w.*` ancestor above it isn't seen, and a second one's rules collide with the first's (a nested one's are dropped). The package's `node`, `worker` and `deno` export conditions tell a server from a client. Appear animations (ADR-0044): under `w.Provider()`, each `w.*` element the server can sample plays its mount animation from the first paint, before the script runs, its rules in a `<style>` the Provider element renders as its first child; `Wardic.make({ appear: false })` turns them off, `"explain"` says in development why an element waits for the JavaScript, `nonce` goes on that `<style>`, and `w.Appear(false)` keeps one element out. On the client, `wardic.hydrate(program, { buildId })` takes `Runtime.hydrate`'s place in the entry: it moves those rules into the head before Foldkit adopts the page, and has the hydration render keep each running animation, which the element's ward takes over where the CSS has got, with no flicker (the Handoff). Give the server's `renderToString` and `wardic.hydrate` one `buildId` (or build both with `@foldkit/vite-plugin`). `Runtime.hydrate` called directly finds a `<style>` the view lacks and rebuilds the Provider element's subtree, and strips each running animation back to its Starting style.
- Scene tests resolve Wardic's Mounts by name: `Scene.Mount.resolve(wardic.Element, Done())`, `wardic.Provider` and `wardic.Presence`.

## Deviations

What this binding does differently from `@wardic/solid`, for what Foldkit gives it:

- **The References and the Tracer reach Wardic through `env`** (ADR-0071, decision 10). A `w.*` element's Mount never sees the program's `resources`, so a Tracer or a Reference set there doesn't reach Wardic's Layer: give them in `Wardic.make({ env })`, as `Layer.merge(DomLive, …)`, until Foldkit gives Mounts services.
- **`wardic.hydrate`, not `Runtime.hydrate`**, for a server-rendered page (above): Foldkit has no head channel for the Appear rules and no hook around its hydration render, so the Handle does both before it hands Foldkit the program.
- **Server rendering is for `makeApplication` programs**: Foldkit's `renderToString` and `Runtime.hydrate` take those alone; a `makeElement` program renders on the client.
- **No Playback controls**: Solid's `animate` returns them (pause, play, speed, time, complete, cancel); on Foldkit the Effect is the handle, awaited for its end and interrupted to stop it (an `interrupt: true` Command's second dispatch), so pause, speed and seek have no place to live.
- **One `w.Provider()`, on the topmost `w.*` element**: Foldkit has no wrapper node, so the element carrying the Provider attribute is the root of the walk that writes the server's styles and samples its Appear animations (above).

The rest is as `@wardic/solid` has it, an attribute for each prop.
